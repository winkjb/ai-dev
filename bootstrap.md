`scripts/Invoke-ScheduledScripts.ps1` (the central dispatcher - one Task Scheduler trigger, reads `data/input/ScriptManifest.csv` + `ScriptRunState.json` to decide what's due) got substantially hardened 2026-07-29, all at Brad's request from prior production experience:
- **Timing guard**: rejects the whole run if triggered outside a configurable window (`-ExpectedHour`/`-ExpectedMinute`/`-MaxTimingDifferenceMinutes`, default 7:00 AM ±15 min) - guards against Task Scheduler misfiring at a weird time (Brad's hit this on multiple customer servers, especially around DST). `-SkipTimingGuard` bypasses it, independent of `-Force`. Logged as `[WARN]`, exits 0 (not a failure).
- **Deliberately did NOT add** a same-day dedup guard (would block a Daily script from re-running if it already succeeded today) - Brad's call: `-Force` already exists for legitimate re-runs, and the timing guard already covers the actual incident (wrong-time firing), so dedup would trade a rare/low-cost duplicate-run risk for real friction on cases where re-running today is wanted.
- **Relative manifest paths**: `Resolve-ScriptDefPath` resolves non-absolute `Path` values against the repo root (`Split-Path $PSScriptRoot -Parent`); absolute paths (the two legacy `C:\Scripts\...` entries, genuinely outside the repo) pass through unchanged. Manifest now uses relative paths for in-repo scripts.
- **Fixed a real splat-binding bug**: array-splat (`@array`) only binds positionally in PowerShell - a manifest `Arguments` value like `-DryRun` was silently landing on the target script's first positional parameter instead of being recognized as a switch (never caught before since `Arguments` had always been blank). Fixed via `ConvertTo-ArgumentHashtable` + hashtable splat for the PowerShell-script branch (python branch untouched - native argv doesn't have this problem).
- **Inter-script delay**: `-DelaySeconds` (default 30, Brad's call from past experience re: API/SMTP pacing) sleeps before each actually-executed script except the first; never a trailing wait after the last; skipped/disabled entries and `-DryRun` don't trigger it.
- **Log rotation + cleanup**: all four of this workspace's logging scripts (the dispatcher's own `Dispatcher_{yyyy-MM}.log`, plus the three `Invoke-CoordinatorReports.ps1` scripts' `scheduled-run-{yyyy-MM}.log`) now write one file per month. New `scripts/Remove-OldLogs.ps1` deletes any older than 12 months by parsing the `yyyy-MM` filename stamp (no line-level parsing needed); registered in the manifest as a Monthly job so it runs on the same hardened dispatcher.

**Critical fix, same day**: production's real Task Scheduler task ("Virtual Administrator Tasks - Daily", runs `C:\VA\scripts\Invoke-ScheduledScripts.ps1`) was silently failing before ever writing a single log line. Root cause: `$PSScriptRoot` is unreliable (empty) at the exact moment PowerShell evaluates **parameter default values**, specifically when a script is launched via `powershell.exe -File "fullpath"` (exactly how Task Scheduler runs things) - but NOT when dot-sourced/invoked from an already-running session, which is how this had been tested all along, so the bug went unnoticed through extensive earlier testing. `Invoke-ScheduledScripts.ps1`'s `$ManifestPath`/`$StatePath` and `Send-ReportEmail.ps1`'s `$SettingsPath` both had this exact anti-pattern (`[string]$X = (Join-Path $PSScriptRoot ...)` as a param default) - both fixed by moving the resolution into the script body (`if (-not $X) { $X = Join-Path $PSScriptRoot ... }`, the same safe pattern already used elsewhere in this workspace, e.g. `Get-CoordinatorProjectData.ps1`, `Connect-Autotask`). Confirmed fixed via genuine `-File` invocation (not just dot-sourcing) on both files, and Brad's confirmed it now works on the real production machine after copying the fix over.

**Not yet fixed, flagged only**: `program-management/ait-networking/scripts/fortigate/Invoke-FortiGateDiscovery.ps1` has this exact same anti-pattern (`$CustomersRoot`/`$RawDataRoot` params). Untouched since it's outside this thread's active scope - worth fixing if that script is ever run via `-File`/Task Scheduler directly.

**Golden testing rule going forward**: when validating anything that will run under Task Scheduler, test with the literal `powershell.exe -File "fullpath" <args>` invocation - not `cd` + relative dot-invocation, even in a fresh process. The two are not equivalent for `$PSScriptRoot`-in-param-defaults purposes, and only `-File` reproduces what Task Scheduler actually does.

## Recent decisions worth knowing

- program-management scope: multi-client/MSP-style, client-facing deliverables, API/export access to assessed platforms already exists, findings stay self-contained (no Service Delivery/PM handoff wiring) for now.
- Retired Python (pandas) report scripts entirely on conversion to PowerShell rather than keeping them alongside (matches precedent from the project-management conversion) - `ticket_summary_flags.py` was deleted 2026-07-21 after `Export-CoordinatorTicketFlagsReport.ps1` was validated against it field-by-field. Same "retire, don't keep alongside" call applied again 2026-07-28 to the old Huntress script.
- Huntress API quirk: its `status` query param rejects values like `sent` as invalid when tested live - status filtering has to happen client-side against the full fetched list (`.Where({ $_.status -ne "resolved" })`), not server-side. Also: company/org ID `0` can be a real account in Autotask (ServIT's own internal company) - `Where-Object { $_ }`-style truthy filters silently drop it; use `$null -ne $_` instead when building lookup batches from IDs that could legitimately be zero.
- Validation bar for any port/rewrite in this workspace: field-by-field diff against a reference/original run, not spot checks - caught two real bugs in the ticket coordinator port (a double-counting bug and a rounding-vs-truncation mismatch between Python and PowerShell) that casual review would have missed. Same rigor applied 2026-07-29 to the dispatcher hardening (every new guard tested live in both directions before considered done, including a fresh fake multi-script manifest entry to actually observe the inter-script delay firing).
- PowerShell gotcha worth remembering for any future manifest `Arguments` use: array-splat (`@array`) binds positionally only - use a hashtable splat (`@hash`) for named/switch parameters, or they silently misbind.
